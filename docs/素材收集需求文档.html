从 Live2D 模型录制导出图片素材，用于桌面宠物应用的角色显示：眼神跟随鼠标、待机眨眼、说话口型——覆盖全部视角方向。

文档版本 v1.2 · 2026-09-26 · 示意图使用占位猫演示，正式素材以实际角色为准 · 本文档为唯一完整需求，请勿使用旧版

一、一分钟看懂

  • 统一画布：所有图片用同一个画布尺寸导出（建议 600×800 竖版、透明背景 PNG），角色在画布中位置固定不动。
  • 三类图：立绘 / 视线方向帧 / 每方向的眨眼与口型帧。视线帧带轻微头部动作时，眨眼和口型必须逐方向提供，才能处处贴合。
  • 照模板命名：放进规定文件夹、按模板命名并填好 manifest，交付后无需改代码直接生效。

三、各类素材详细要求（含示意图）

1. 立绘 poses/

完整角色、透明背景，姿态自然。必交一张默认待机（idle）；如有其他常用姿态（开心、疑问等）一并交付，命名对应 manifest。

导出后会在应用中缩放显示，画布内角色尽量占满高度、四周留少量边距。

2. 视线方向帧 gaze/（3×3 共 9 张）

应用会让角色眼神跟随屏幕上的鼠标——鼠标在角色的 9 个方位时切换到对应帧。录制时只改视线（和头部朝向）参数，身体、表情、位置全部保持与立绘一致。允许加入轻微自然的头部倾斜/身体随动（效果更好），但此时第四、五节的每方向眨眼与口型帧为必交项。

命名规则g{c}r{r}.png：g=左右列（g0 看左、g1 正中、g2 看右），r=上下行（r0 看上、r1 正中、r2 看下）。

想更顺滑可升级 5×5（25 张，g0～g4 / r0～r4），manifest 里把 cols/rows 改成 5 即可。

3. 眨眼帧 blink/（每方向 1～2 张，共 9～18 张）

待机时角色自动眨眼。要求每个视线方向各有一套闭眼帧：在该方向的头部姿态基础上，仅把「眨眼」参数设为约 50%（半闭 _half）和 100%（全闭），导出整帧。睁开状态不需要单独导出（直接显示视线帧本体）。

命名规则全闭 blink/g{c}r{r}.png；半闭 blink/g{c}r{r}_half.png。例如看向左上时眨眼的全闭帧是 blink/g0r0.png。

4. 口型帧 mouth/（每方向 1～2 张，共 9～18 张）

角色说话时口型随音量开合，与眨眼同理，每个视线方向各有一套张嘴帧：在该方向头部姿态基础上，仅把「嘴张合」参数设为约 50%（半开 _half）和 100%（全开）。闭口状态不需要单独导出。

命名规则全开 mouth/g{c}r{r}.png；半开 mouth/g{c}r{r}_half.png。

四、对齐规范（最重要）

应用通过逐帧叠加切换实现动画：所有帧的画布、角色位置必须完全一致，只允许目标参数变化。错位会导致运行时角色抖动 / 鬼影。

自查方法：把「某方向的视线帧 + 该方向的闭眼帧」叠在一起，来回切换图层可见性——只有眼睛在变、画面其他部分纹丝不动即为合格。9 个方向逐一检查；口型帧同理。

五、Live2D Cubism 导出步骤

  1. 建场景：动画工作区新建场景，画布设为目标尺寸（如 600×800），摆好默认姿势并固定模型位置。
  2. 立绘：所有参数归默认值，导出 poses/idle.png；其他姿态逐个摆好导出。
  3. 视线 9 帧：仅把「视线 X / 视线 Y」（或头部角度参数）依次设到 9 个格位，逐格导出 gaze/g{c}r{r}.png。
  4. 眨眼 18 张：对每个视线格位——固定该方向参数，仅把「眨眼」设为 50% / 100%，导出 blink/g{c}r{r}_half.png 与 blink/g{c}r{r}.png。
  5. 口型 18 张：对每个视线格位——固定该方向参数，仅把「嘴张合」设为 50% / 100%，导出 mouth/g{c}r{r}_half.png 与 mouth/g{c}r{r}.png。
  6. 全部使用透明背景（PNG）导出，不要带背景色。
批量技巧：在动画工作区把「9 方向 × 表情参数」排成动画序列，用「批量输出 PNG（序列帧）」一次性导出全部 36 张，再按规则重命名，效率最高。

六、交付内容与方式

把以下目录打包 zip 交付（manifest.json 由制作者或接收方按模板填写均可）：

角色素材包/
├── manifest.json
├── CREDITS.md          （来源与授权说明：模型名、制作者、授权范围）
├── poses/
│   ├── idle.png        （必交）
│   └── happy.png       （可选，其他姿态同理）
├── gaze/
│   ├── g0r0.png  g1r0.png  g2r0.png
│   ├── g0r1.png  g1r1.png  g2r1.png
│   └── g0r2.png  g1r2.png  g2r2.png
├── blink/
│   ├── g0r0.png  g1r0.png  g2r0.png   （全闭）
│   ├── g0r1.png  g1r1.png  g2r1.png
│   ├── g0r2.png  g1r2.png  g2r2.png
│   └── *_half.png                     （半闭 9 张，命名如 g0r0_half.png）
└── mouth/
    ├── g0r0.png  g1r0.png  g2r0.png   （全开）
    ├── g0r1.png  g1r1.png  g2r1.png
    ├── g0r2.png  g1r2.png  g2r2.png
    └── *_half.png                     （半开 9 张）

manifest.json 模板（PNG 版）

{
  "name": "角色名",
  "version": 1,
  "canvas": { "width": 600, "height": 800 },
  "poses": [
    { "id": "idle",  "name": "待机", "src": "poses/idle.png" },
    { "id": "happy", "name": "开心", "src": "poses/happy.png" }
  ],
  "gaze":   { "pose": "idle", "cols": 3, "rows": 3, "srcPattern": "gaze/g{c}r{r}.png" },
  "blink":  {
    "perGaze": true,
    "patterns": {
      "1": "blink/g{c}r{r}_half.png",
      "2": "blink/g{c}r{r}.png"
    },
    "frames": [ { "level": 2, "src": "blink/g1r1.png" },
                { "level": 1, "src": "blink/g1r1_half.png" } ]
  },
  "mouth":  {
    "perGaze": true,
    "patterns": {
      "1": "mouth/g{c}r{r}_half.png",
      "2": "mouth/g{c}r{r}.png"
    },
    "frames": [ { "level": 2, "src": "mouth/g1r1.png" },
                { "level": 1, "src": "mouth/g1r1_half.png" } ]
  },
  "themes": { "day": { "name": "日间", "starCount": 0 },
              "night": { "name": "夜间", "starCount": 60 } },
  "testAudio": "audio/test.wav"
}

说明：blink/mouth 用 perGaze 模式逐方向加载；frames 引用正中方向（g1r1）的图作为兜底——某方向帧意外缺失时自动回退，不会白屏。多姿态时全部表情帧基于默认姿态（idle）录制。

七、交付前自查清单

  • 所有图片画布尺寸完全一致（同一场景导出）
  • 全部为透明背景 PNG，无背景色块
  • 角色在画布中位置固定：逐帧切换时只有眼睛/嘴在动
  • 视线 9 帧方向正确（g0 左 / g2 右，r0 上 / r2 下），身体与表情无变化
  • 每方向闭眼帧与该方向视线帧叠合检查通过（9 组），闭眼完全闭合且过渡自然
  • 每方向张嘴帧与该方向视线帧叠合检查通过（9 组），张合过渡自然
  • 半闭/半开帧位于睁开与全闭/全开之间，无跳变
  • 文件命名与 manifest 模板一致（区分大小写，_half 后缀）
  • 已附 CREDITS.md（模型来源、制作者、授权范围）
最低可用交付：立绘 1 张 + 视线 9 张 + 每方向全闭 9 张 + 每方向全开 9 张（共 28 张）即可获得完整体验；半闭/半开后续补充不影响上线。
