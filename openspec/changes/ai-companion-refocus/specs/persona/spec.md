# persona 规格（增量）

## Purpose

定义聊天角色人设能力：桌宠的对话回复必须始终符合一个可配置的角色人设，让用户感到"是这个角色在和我说话"，而非通用语言模型。

## ADDED Requirements

### Requirement: 人设配置与默认内置

设置页必须提供人设提示词的编辑区（多行文本），保存后持久化、重启保持。应用必须内置一份默认人设：用户未做任何配置时，聊天即按默认人设运作，无需先去设置。人设为空（用户清空后保存）时必须回退到默认人设。

#### Scenario: 首次启动默认人设生效
- **WHEN** 用户全新安装后未触碰任何设置直接发起对话
- **THEN** 回复体现内置默认人设的性格与自称，无需用户先配置

#### Scenario: 编辑人设持久化
- **WHEN** 用户修改人设并保存，重启应用后再发起对话
- **THEN** 回复按修改后的人设呈现

#### Scenario: 清空人设回退默认
- **WHEN** 用户清空人设内容并保存后发起对话
- **THEN** 应用按默认人设回复，而非以无系统提示的裸对话请求模型

### Requirement: 人设注入 LLM 对话

所有 LLM 对话请求必须将当前生效的人设作为系统提示注入（位于多轮历史之上）；连续多轮对话中人设保持生效。人设仅作用于 LLM 请求，不得改变语音识别、语音合成与播放的行为。

#### Scenario: 多轮对话保持人设
- **WHEN** 用户连续进行多轮对话
- **THEN** 每一轮回复都保持人设设定的语气与自称

#### Scenario: 人设不影响语音链路
- **WHEN** 用户修改人设后使用语音输入与语音回复
- **THEN** 识别与合成行为与修改前一致
