# 设计：AI 陪伴桌宠重聚焦（视线跟随 + 固定音色聊天）

## Context

动机见 proposal.md。当前代码事实：聊天 UI 已按 `eadf4ae` 卸载（聊天操作栏、字幕框、设置页聊天区块），但底层 `pipeline.js`（模式切换 / ASR→LLM→TTS 链路 / 打断代际）、`recorder.js`、`player.js` 完整保留；`proxy.chatComplete(messages)` 由调用方组织消息，尚无系统提示机制；TTS 仅"OpenAI 兼容"一种提供方式。视线跟随（九方向视线帧）已实现并通过素材校验，本变更不改其需求。

引擎部分承接被取代变更 `gpt-sovits-voice-engine` 的设计（engine.json 契约、EngineManager 状态机、分离式语音包交付），本设计在其基础上做"固定单音色"简化。

## Goals / Non-Goals

**Goals:**
- 聊天三模式（按键说话 / 免提 / 文字）回归可用，链路行为与 voice-chat 既有规格一致
- 人设注入后所有 LLM 对话"像这个角色在说话"，人设可配置、有默认
- GPT-SoVITS 引擎包一键可得、进程免维护；固定目标音色导入即用
- 引擎路线可冒烟自检（不依赖真实 2~3GB 引擎包）

**Non-Goals:**
- 不做音色克隆（参考音频零样本）与多音色切换（后续迭代）
- 不做引擎自动更新、非 Windows 引擎包、模型训练 UI
- 不改动视线跟随 / 素材管线 / 播放口型链路的需求级行为
- 不改变 ASR 仍为用户配置的 OpenAI 兼容服务

## Decisions

### D1：聊天 UI 以卸载提交为基准恢复，不重写

以 `eadf4ae` 的 diff 为恢复蓝本（该提交完整记录了被移除的聊天操作栏、字幕框、设置页区块），反向恢复后再叠加本变更的新 UI（人设编辑、语音引擎区块、TTS 类型选项）。期间其他提交对同文件的改动（如设置页大小滑杆）逐一保留。备选"按现需求从零重写 UI"被否：卸载仅一周、无需求变化，重写只引入回归风险。

### D2：人设在主进程统一注入

`proxy.chatComplete(messages)` 内部把 system prompt 插到消息队列头部，渲染端只传对话历史。人设存 `prefs.persona`（普通文本，非敏感，不走加密 keys）；取值为空时回退 `app/shared/constants.js` 的 `DEFAULT_PERSONA` 内置默认。备选"渲染端自行组装"被否：主进程是所有 AI 请求的唯一出口（Key 不进渲染端的原则同源），在此注入可让未来新增的 LLM 调用（如主动搭话）自动携带人设，且冒烟可在主进程侧断言注入结果。

### D3：引擎契约与进程监督沿用原设计

完整承接 `gpt-sovits-voice-engine/design.md` 的 D1/D2/D5/D6：ZIP + `engine.json` 清单契约（解压到 `userData/voice-engine/`，不硬编码引擎内部布局）；EngineManager 状态机（absent → downloading → installed → starting → ready → error）+ 懒启动 + `/ping` 探活（上限 90 秒）+ 崩溃重启 ≤3 次 + 退出时 `taskkill /T`；`net.fetch` 流式下载 + 大小/SHA-256 校验 + 一个轻量纯 JS unzip 依赖。

### D4：固定单音色简化（对原设计的修改）

音色目录 `userData/voice-models/<name>/` 仅保留 `model/`（gpt.ckpt、sovits.pth）+ `voice.json`；删除原设计的 `ref/`（零样本克隆）与模式切换 UI。设置页音色区块收敛为：导入模型 → 启用 → 试听。`ttsType: 'gptsovits' | 'openai'`：**全新安装默认 `gptsovits`**；升级用户该字段缺失时按 `openai` 处理（延续其既有可用路线，设置页引导切换本机引擎），这与"不得未经用户确认自动回退云端"的规格不冲突——运行中任何时刻都不做静默改道。

### D5：引擎冒烟用 stub，不依赖真实引擎包

冒烟模式（`--smoke`）下 EngineManager 启动一个 Node 内置 stub 脚本（模拟 `/ping` 与 `/tts` 返回固定 WAV）代替真实引擎，验证：状态机流转、端口顺延、崩溃重启、合成接入播放队列、人设注入断言。真实引擎包的端到端验收留给带真实资产的人工清单（引擎包由委托人托管，开发期不可得）。备选"冒烟下载真实引擎包"被否：2~3GB 依赖外网，冒烟必须离线可跑。

### D6：引擎包制作规范文档随本变更交付

`docs/voice-engine-spec.md`（承接原 D6）：目录布局、engine.json 字段、启动参数约定、制作方法。委托人按规范打包含托管，桌宠侧只依赖契约。

## Risks / Trade-offs

- [聊天 UI 恢复与后续提交冲突] → 恢复时逐文件核对 `eadf4ae` 之后的所有改动，冒烟全绿后再叠加新功能
- [引擎首次加载 10~60 秒] → 懒启动 + 状态文案 + 设置页"预启动"热身入口
- [CPU 推理 5~15 秒/句] → 文字先出、语音后到的异步体验；设置页提示硬件预期
- [人设过长推高 token 成本] → 默认人设控制在数百字内；编辑区显示字数提示
- [下载 2~3GB 无断点续传] → 进度可见 + 失败重下 + SHA-256 校验（v1 取舍，承接原设计）
- [默认 TTS 路线变化引起升级用户困惑] → 升级用户保持 openai 行为 + 设置页引导；见 D4

## Migration Plan

纯新增 + UI 恢复，向后兼容。发布顺序：桌宠新版本（引擎管理 UI 在未下载引擎时置灰）→ 委托人发布引擎包与音色模型 → 用户一键下载启用。回滚：TTS 切回 openai 类型即可；引擎目录可手动删除；聊天 UI 恢复若出问题按提交粒度回退。

## Open Questions

- 引擎包与音色模型的下载地址、CUDA/CPU 版本策略（委托人决定，桌宠按契约兼容，不阻塞开发）
- 默认人设的具体文案（角色性格、自称、语气）——需要委托人提供角色设定，架构不依赖其内容，可在实施期内补
- 聊天是否保留语音输入三模式（proposal 规划假设①）——如评审时裁剪，仅影响 D1 的恢复范围与 tasks 增减，不影响引擎与人设设计
