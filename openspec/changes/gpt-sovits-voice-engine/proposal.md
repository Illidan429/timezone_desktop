# 提案：GPT-SoVITS 语音引擎集成（分离式语音包）

## Why

桌宠的语音回复目前依赖用户自行配置云端 TTS（OpenAI 兼容格式），存在两个问题：一是云端预设音色无法还原目标主播的音色，二是持续调用产生费用。用户希望桌宠**内置 GPT-SoVITS 语音克隆引擎**：由委托人提供预训练音色模型，普通用户安装后零配置获得目标音色的本地语音合成——免费、离线、音色还原。

为避免安装包从 78MB 膨胀到数 GB，采用**分离式语音包**交付：桌宠安装包保持轻量；首次启用语音时引导用户一键下载 GPT-SoVITS 推理引擎包（约 2~3GB）并自动接入。

## What Changes

- **语音引擎包管理**：应用内一键下载 GPT-SoVITS 推理引擎包（ZIP，含嵌入式 Python 运行时 + 推理代码 + 基础模型），自动解压到本地用户目录、校验版本、支持重新下载/修复；下载源地址可在设置中配置（由委托人托管分发）
- **引擎进程管理**：主进程以子进程方式启动/停止 GPT-SoVITS 的 api_v2 HTTP 服务（默认端口 9880，冲突自动顺延），就绪探活、崩溃自动重启（有限次）、随应用退出而停止；引擎状态（未下载/下载中/启动中/就绪/合成中/错误）在设置页与语音流程中可见
- **音色模型管理（双模式）**：
  - **预训练模型**：委托人分发训练好的 GPT/SoVITS 权重（gpt.ckpt + sovits.pth），用户在设置中一键导入并启用
  - **零样本克隆**：用户上传目标声音的参考音频（3~10 秒）及对应文字，通过 api_v2 的参考音频参数实现克隆合成
- **TTS 提供方扩展**：TTS 类型从单一的"OpenAI 兼容"扩展为可选 **"GPT-SoVITS（本机引擎）"**，合成请求走本机引擎 api_v2 接口返回 WAV 音频，接入现有播放队列与口型同步（零播放层改动）；未就绪时明确提示，不自动回退云端
- **交付物不变**：桌宠安装包/便携版保持现有体积；语音引擎包与音色模型由委托人另行分发
- 不在本期范围：模型训练流程（训练用官方工具线下完成后分发产物）、云端 TTS 行为变更、非 Windows 平台

## Capabilities

### New Capabilities

- `voice-engine`: 语音引擎包管理——引擎包下载/校验/解压/版本管理，GPT-SoVITS api_v2 子进程的启动、探活、端口分配、崩溃重启与随应用退出
- `voice-model`: 音色模型与克隆——预训练模型导入启用、参考音频零样本克隆的配置管理、TTS 类型扩展为可选本机引擎、合成请求接入播放链路的状态反馈

### Modified Capabilities

（无——现有规格均不受需求级影响；voice-chat 中的 TTS 行为按其规格仍为"用户配置的服务"，本变更为其新增一种本地提供方式）

## Impact

- **新增代码**：主进程新增引擎管理模块（下载/解压/子进程监督）与 GPT-SoVITS API 客户端；渲染端设置页新增"语音引擎"区块（状态、下载、模型导入、参考音频、试听）；TTS 调用层增加 provider 分支
- **依赖**：仅使用 Node 内置能力（下载/解压/子进程）；不引入重型依赖
- **分发**：语音引擎包与音色模型的下载地址由委托人配置和托管；GPT-SoVITS 为 MIT 许可，打包分发合规，需在 CREDITS 中署名
- **风险**：引擎首次加载模型需 10~60 秒（必须异步化并反馈状态）；纯 CPU 推理较慢（5~15 秒/句，需提示预期）；约 2~3GB 的引擎包下载需要断点与校验
- **不受影响**：现有 OpenAI 兼容 TTS 路线保留并存；聊天/播放/口型链路不变
