# voice-chat 规格（增量）

## Purpose

定义与应用角色的语音聊天能力：用户可自行配置 AI 服务（语音识别 ASR、大模型 LLM、语音合成 TTS，OpenAI 兼容格式）并逐项测试可用性；支持按键说话、免提监听、文字输入三种交互模式切换；完成"输入 → 回复 → 语音播放 + 口型 + 字幕"的完整对话链路。

## ADDED Requirements

### Requirement: API 配置

设置页必须提供三类服务配置（ASR、LLM、TTS），每类包含服务地址（Base URL）、API Key、模型名；配置持久化，重启保持。API Key 必须以不明文形式存储，界面不得回显完整明文 Key。

#### Scenario: 保存配置
- **WHEN** 用户填写三类服务的地址、Key、模型名并保存后重启应用
- **THEN** 配置保持，界面不显示完整 Key 明文

### Requirement: API 配置测试

每类服务配置必须配有"测试"按钮：点击后向该服务发起一次最小真实请求，并在界面明确显示成功或失败及失败原因（网络不通、鉴权失败、模型名错误等分类提示），帮助用户自助排查。

#### Scenario: 测试连通的 TTS 服务
- **WHEN** 用户填好 TTS 配置并点击"测试"
- **THEN** 界面显示测试成功（可附带一小段合成音试听）

#### Scenario: 测试失败给出原因
- **WHEN** 用户填错 API Key 后点击"测试"
- **THEN** 界面提示鉴权失败类错误，而非笼统的"失败"

### Requirement: 三种交互模式可切换

应用必须支持三种输入模式并可随时切换、选择持久化：
- **按键说话**：按住指定按钮（或快捷键）录音，松开后结束录音并送识别；
- **免提监听**：持续监听麦克风，自动检测说话开始与结束并发起识别；
- **文字输入**：在输入框打字发送。

未配置对应 API 时，相关模式必须置灰并引导到设置页。

#### Scenario: 按键说话
- **WHEN** 用户按住说话按钮讲一句话后松开
- **THEN** 录音结束并送识别，角色进入回复流程

#### Scenario: 免提监听自动分段
- **WHEN** 免提模式下用户开口说一句话后停顿
- **THEN** 应用自动截取该段语音送识别，无需任何按键

#### Scenario: 未配置 ASR 时模式禁用
- **WHEN** ASR 未配置且用户切换到免提模式
- **THEN** 模式不可用并提示前往设置配置

### Requirement: 对话链路

用户输入（语音或文字）必须经 LLM 生成回复，回复文本以字幕/气泡展示并同时经 TTS 合成语音播放，播放期间角色口型同步。链路任一环节失败（识别失败、模型超时、合成失败）必须给出行内提示并保持应用可用，不得静默无响应。

#### Scenario: 语音提问语音回答
- **WHEN** 三类 API 已配置，用户语音提问
- **THEN** 界面依次呈现识别出的提问、文字回复，角色开口播报回复且口型同步

#### Scenario: 环节失败提示
- **WHEN** TTS 配置失效时用户发起对话
- **THEN** 界面提示合成失败及原因，文字回复仍正常展示

### Requirement: 对话上下文

会话必须维持多轮对话上下文，后续回复与前文连贯；用户必须能一键清空上下文开始新会话。

#### Scenario: 多轮连贯
- **WHEN** 用户先问"你喜欢什么颜色"得到回答后，再问"为什么"
- **THEN** 角色的回复与前问语境连贯

### Requirement: 打断

角色正在语音回复时，用户必须能通过点击角色或发起新输入打断播放；打断后播放立即停止、口型闭合，应用接受新输入。

#### Scenario: 打断长回复
- **WHEN** 角色长回复播放中用户点击角色并说新内容
- **THEN** 播放立即停止，新输入被正常处理
